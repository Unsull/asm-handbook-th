# เริ่มต้นใช้งานคู่มือ

คู่มือฉบับนี้เขียนสำหรับผู้เริ่มเรียน Cybersecurity, Developer, QA, System Administrator และ DevOps ที่อยากวิเคราะห์ความเสี่ยงของระบบอย่างเป็นขั้นตอน โดยไม่จำเป็นต้องมีระบบองค์กรจริงให้ทดลอง

## อ่านอย่างไรให้เข้าใจ

1. อ่าน **แนวคิดหลัก** แล้วลองสรุปด้วยคำพูดตัวเองว่ากำลังปกป้องสินทรัพย์อะไร จากใคร และเพราะอะไร
2. อ่าน **กรณีศึกษา** ที่ใช้ร้านค้าออนไลน์ ระบบจองห้องพัก และ SaaS จำลอง เพื่อเชื่อมกับการทำงานจริง
3. ทำ **Workshop** ในสภาพแวดล้อมที่ได้รับอนุญาตเท่านั้น จด Before/After และค่าสังเกตจริง
4. ทำ **Quiz** เพื่อทบทวน; หากผิด ให้กลับไปอ่านหลักการ ไม่ใช่ท่องเฉลย
5. บันทึกคำศัพท์ใหม่ใน [อภิธานศัพท์](/glossary/) และอ่านเอกสารจาก [References](/references/)

::: tip เริ่มต้นแบบไม่ติดตั้งเครื่องมือ
สามารถอ่านแนวคิด กรณีศึกษา และทำ Quiz ทั้ง 11 บทได้จากเว็บก่อน แล้วค่อยทำ Workshop ภายหลัง
:::

## เครื่องมือสำหรับ Lab

| เครื่องมือ | ใช้สำหรับ | จำเป็นทุกบทหรือไม่ |
|---|---|---|
| Browser / VS Code | อ่านและแก้ Markdown | ไม่ (อ่านเว็บได้) |
| Python 3.11+ | CSV, Risk, Discovery, Synthetic API Labs | บางบท |
| Docker Desktop / Docker Engine | Container Network และ Monitoring Lab | บางบท |
| Nmap | Network Scanning เฉพาะเป้าหมายที่ได้รับอนุญาต | บทที่ 5/7 |
| Node.js 22+ | รันเว็บไซต์ VitePress ในเครื่อง | สำหรับผู้แก้ไขเว็บ |

## การประเมินความมั่นคงปลอดภัย

ตัวอย่าง Threat และ CVE ในคู่มือมีไว้สอนการประเมินเท่านั้น **ไม่ได้ยืนยันว่าองค์กรหรือบริการจริงมีช่องโหว่** การตรวจระบบต้องกำหนด Scope, ขออนุญาต, เก็บหลักฐาน และระบุข้อจำกัดของวิธีตรวจเสมอ

# อภิธานศัพท์ — ASM Glossary

รวม 78 คำศัพท์ที่ใช้ในคู่มือ พร้อมคำอธิบายภาษาไทยเบื้องต้น คำบางคำมีการตีความเฉพาะบริบท ควรกลับไปอ่านตัวอย่างในบทที่เกี่ยวข้อง

| คำศัพท์ | ความหมายโดยย่อ |
|---|---|
| **Access Control** | มาตรการกำหนดว่า Identity ใดทำอะไรกับ Resource ใดได้บ้าง |
| **Accountability** | ความสามารถระบุและตรวจสอบย้อนหลังว่าการกระทำเกิดจาก Identity/Process ใด |
| **Agent-based Discovery** | การตรวจสินทรัพย์โดยใช้ Software Agent บนอุปกรณ์เป้าหมาย |
| **ALE** | Annualized Loss Expectancy; ความเสียหายคาดหมายต่อปีภายใต้โมเดล |
| **Anomaly Detection** | การค้นหาข้อมูลหรือพฤติกรรมที่ต่างจาก Baseline |
| **ARO** | Annualized Rate of Occurrence; ความถี่คาดหมายต่อปี |
| **Asset** | ทรัพยากรที่มีคุณค่าต่อองค์กร |
| **Asset Criticality** | ความสำคัญของสินทรัพย์ต่อ Business Objectives |
| **Asset Enrichment** | การเพิ่ม Context เช่น Owner, Data Sensitivity, Dependencies |
| **Asset Inventory** | ทะเบียนที่อธิบายสิ่งที่องค์กรมีและบริบทของแต่ละ Asset |
| **Attack Path** | เส้นทางของเงื่อนไขที่อาจนำไปสู่เป้าหมายโจมตี |
| **Attack Surface** | ชุดช่องทาง สิทธิ์ และจุดติดต่อที่อาจถูกใช้เป็นทางเข้าหรือกระทบระบบ |
| **Attack Surface Analysis** | การวิเคราะห์ Entry Points, Flows, Boundaries และ Controls |
| **Attack Vector** | วิธีหรือเทคนิคที่ผู้โจมตีใช้ผ่าน Surface |
| **Authentication** | การตรวจสอบอัตลักษณ์ของผู้เรียกใช้งาน |
| **Authorization** | การตัดสินว่าตัวตนที่ยืนยันแล้วมีสิทธิ์ทำสิ่งใด |
| **BIA** | Business Impact Analysis; การวิเคราะห์ผลกระทบเมื่อกระบวนการธุรกิจหยุดหรือเสียหาย |
| **BOLA** | Broken Object Level Authorization; การตรวจสิทธิ์ระดับ Object ที่ผิดหรือไม่ครบ |
| **CAASM** | Cyber Asset Attack Surface Management; เน้นรวมบริบทสินทรัพย์จากหลายแหล่ง |
| **CISA KEV** | Known Exploited Vulnerabilities; รายการ CVE ที่มีหลักฐานการใช้โจมตีจริง |
| **Cloud IAM** | การจัด Identity, Roles และ Permissions ใน Cloud |
| **CMDB** | Configuration Management Database สำหรับ Items/Relationships ที่องค์กรบริหาร |
| **Compensating Control** | มาตรการทดแทนเมื่อติดข้อจำกัดในการใช้มาตรการหลัก |
| **Confidentiality** | ความลับของข้อมูล |
| **Configuration Drift** | ความต่างของ Actual Configuration จาก Approved/Desired State |
| **Crown Jewel** | สินทรัพย์หรือความสามารถที่สำคัญสูงสุดต่อภารกิจ |
| **Crypto Agility** | ความสามารถในการเปลี่ยน Cryptographic Algorithms/Providers อย่างควบคุม |
| **CVE** | Common Vulnerabilities and Exposures; Identifier ของรายการช่องโหว่ |
| **CVSS** | Common Vulnerability Scoring System; ตัวชี้วัดความรุนแรงเชิงเทคนิค |
| **Data Classification** | การแบ่งระดับความอ่อนไหวของข้อมูล |
| **Data Flow Diagram** | แผนภาพแสดงการเคลื่อนย้ายข้อมูลระหว่าง Elements |
| **Data Minimization** | การเก็บและใช้ข้อมูลเท่าที่จำเป็นต่อวัตถุประสงค์ |
| **Default Deny** | ปฏิเสธการเข้าถึง เว้นแต่มีกฎอนุญาตชัดเจน |
| **Dependency** | ความสัมพันธ์ที่ส่วนหนึ่งต้องอาศัยอีกส่วนหนึ่งในการทำงาน |
| **DevSecOps** | การบูรณาการ Security เข้ากับ Development และ Operations |
| **EASM** | External Attack Surface Management; มอง Resources/Exposure จากภายนอก |
| **Edge Computing** | ประมวลผลข้อมูลใกล้แหล่งกำเนิดแทนการส่งไปส่วนกลางทั้งหมด |
| **Entry Point** | จุดที่ Input/Request/Instruction เข้าสู่ระบบ |
| **EPSS** | Exploit Prediction Scoring System; ประเมินโอกาสใช้ CVE ในวงกว้างช่วง 30 วัน |
| **Exposure** | สภาพที่ Resource/Capability ถูกเปิดให้เข้าถึงจากขอบเขตหนึ่ง |
| **False Negative** | มีเหตุ/สภาพที่ควรตรวจพบ แต่ Detection ไม่แจ้ง |
| **False Positive** | Detection แจ้งเงื่อนไขผิดปกติ ทั้งที่ไม่ใช่เหตุเป้าหมายจริง |
| **Finding** | ข้อค้นพบที่ต้องตรวจ/แก้ พร้อมหลักฐานและสถานะ |
| **Grover’s Algorithm** | อัลกอริทึม Quantum Search ที่มีนัยต่อระดับความปลอดภัยของบาง Primitive |
| **HSM** | Hardware Security Module สำหรับปกป้องหรือดำเนินการเกี่ยวกับ Cryptographic Keys |
| **Incident Response** | การตรวจสอบ รับมือ จำกัดผลกระทบ ฟื้นฟู และเรียนรู้จาก Incident |
| **Integrity** | ความถูกต้องครบถ้วนของข้อมูล/การทำงาน |
| **Inventory Freshness** | ระดับความใหม่ของข้อมูลที่ใช้ยืนยันสินทรัพย์ |
| **Least Privilege** | การให้สิทธิ์เท่าที่จำเป็นต่อหน้าที่ |
| **Likelihood** | การประเมินความเป็นไปได้ของเหตุการณ์ตามบริบทและเกณฑ์ |
| **LINDDUN** | แนวทาง Threat Modeling ที่เน้น Privacy |
| **Machine Identity** | ตัวตนของ Application/Service/Automation แทนมนุษย์ |
| **Mean Time to Detect** | เวลาเฉลี่ยที่ใช้ตรวจพบเหตุการณ์ตามคำนิยามขององค์กร |
| **Mitigation** | มาตรการลดโอกาสเกิดหรือผลกระทบของความเสี่ยง |
| **ML-DSA** | มาตรฐาน Post-Quantum Digital Signature ของ NIST FIPS 204 |
| **ML-KEM** | มาตรฐาน Post-Quantum Key Encapsulation ของ NIST FIPS 203 |
| **Network Segmentation** | การแบ่ง Network Zones และควบคุมการเชื่อมระหว่างกัน |
| **OpenAPI** | รูปแบบ Specification สำหรับอธิบาย HTTP APIs |
| **PASTA** | Process for Attack Simulation and Threat Analysis |
| **PQC** | Post-Quantum Cryptography; Algorithm ที่ออกแบบเพื่อรับมือภัย Quantum |
| **PromQL** | ภาษาสืบค้น Time-series Metrics ของ Prometheus |
| **Recovery Point Objective** | ปริมาณการสูญเสียข้อมูลย้อนหลังที่ยอมรับได้สำหรับการกู้คืน |
| **Recovery Time Objective** | เป้าหมายระยะเวลาฟื้นฟูบริการตามนโยบาย |
| **Remediation** | การแก้ไขปัญหาหรือจัดการสาเหตุภายใต้เกณฑ์ที่กำหนด |
| **Residual Risk** | ความเสี่ยงที่เหลือหลัง Controls และ Actions ที่มีผลจริง |
| **Risk Appetite** | ระดับ/รูปแบบความเสี่ยงที่องค์กรยอมรับตาม Governance |
| **RPO** | Recovery Point Objective |
| **RTO** | Recovery Time Objective |
| **SBOM** | Software Bill of Materials; รายการองค์ประกอบซอฟต์แวร์ |
| **Security Posture** | สถานะภาพรวมของ Controls และความเสี่ยงตามช่วงเวลา |
| **Shadow IT** | เทคโนโลยีที่ใช้นอกกระบวนการกำกับดูแลขององค์กร |
| **Shor’s Algorithm** | อัลกอริทึม Quantum ที่คุกคาม RSA/ECC เมื่อมี Quantum Computer เพียงพอ |
| **STRIDE** | Spoofing, Tampering, Repudiation, Information Disclosure, DoS, Elevation of Privilege |
| **Threat** | สาเหตุ/เหตุการณ์ที่อาจสร้างผลกระทบ |
| **Threat Modeling** | การระบุสมมติฐานภัยคุกคามและ Controls จาก Architecture/Flows |
| **Trust Boundary** | ขอบเขตที่ระดับความเชื่อถือหรืออำนาจการควบคุมเปลี่ยน |
| **Vulnerability** | จุดอ่อนที่อาจถูกใช้ประโยชน์ |
| **Zero Trust** | แนวคิดตรวจและควบคุมการเข้าถึงอย่างต่อเนื่อง ไม่เชื่อเพียง Network Location |

## หากศัพท์เดียวมีหลายความหมาย

คำอย่าง `Risk`, `Asset`, `Exposure` และ `Criticality` ต้องอธิบายพร้อม Scope และเกณฑ์ที่ใช้ในการประเมิน อย่านำ Ratings จากคนละ Framework มาเทียบตรง ๆ โดยไม่ปรับบริบท
